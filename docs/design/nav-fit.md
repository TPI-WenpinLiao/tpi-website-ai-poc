# header 選單寬度實測（M3-01）

確認 header 第一層 6 項加上工具列（搜尋、語系切換、聯絡我們），en、vi 在 1280px 寬度能否放進一列。對應 [`navigation.md`](../ia/navigation.md)「待確認」。

## 結論

- zh-TW 放得下，餘裕 269px 以上
- en 只有在 Arial 寬度的字型下放得下（餘裕 15–54px）；「產業方案」用較長的譯名（`en-long`）或較寬的字型就放不下
- vi 在三種字型都放不下（差 23–148px），主因是「Câu Chuyện Thành Công」
- 依 `navigation.md` 的備案，把「成功案例」移到「資源」底下（`*-long-fallback`）後，en、vi 最壞情況仍有 65px 以上餘裕

是否採用備案、只用在 en、vi 還是三語統一，列在 M3-01 PR 待使用者決定；決定前不改 `navigation.csv`。

## 量測條件

- 頁面：`/wireframes/navigation` 的「1280px 寬度測試」，viewport 1280px，版面最大寬度 `--content-max-width`（72rem）扣掉左右 padding，可用 1120px
- 標籤：zh-TW 讀自 `navigation.csv`。en、vi 是量測用標籤，不是翻譯（選單文字屬 M7）：有現站對應的沿用現站 header 文字（`inventory.csv` 的 `nav_location`），「產業方案」現站沒有，用暫譯，並以較長的譯名（`*-long`）當最壞情況。定義在 `src/lib/wireframe/header-labels.ts`
- 間距：第一層項目左右各 `--wf-space-3`（12px）、搜尋按鈕 44px 寬，都是 wireframe 的暫定值；M3-02 定正式 token 與字型後要重跑
- 字型：容器沒有 Segoe UI、PingFang 等系統字型，改用三種已安裝的字型量測，中文一律 fallback 到 WenQuanYi Zen Hei。Liberation Sans 與 Arial 等寬；Inter 是常見的 UI 字型；DejaVu Sans 偏寬，當最壞情況
- 另外檢查所有 wireframe 頁在 375px 與 1280px 是否出現水平捲動

## 重現方式

```bash
npm run build
node scripts/wireframe/nav-fit.mjs           # 量測並改寫下方自動產生的段落
node scripts/wireframe/nav-fit.mjs --check   # 只比對，不寫檔；過期或有頁面水平捲動時 exit 1
```

結果取決於執行環境安裝的字型，所以沒有接進 `npm run check`。script 會先確認上述字型都已安裝，缺字型時直接失敗，不會靜默改用其他字型。同一個環境連跑兩次，輸出相同。
