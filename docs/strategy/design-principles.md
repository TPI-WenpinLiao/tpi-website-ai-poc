# 設計原則與參考（#166）

本檔是分階段流程設計概念階段的第一份產出（`.claude/skills/design-concept/SKILL.md`「1. 設計原則」「2. 參考對照」）。它決定試點頁（`docs/strategy/site-profile.md`「試點頁面」）在畫面上要傳達什麼，用來否決不符合的設計。第 2 階段三個方向的首頁原型（`docs/strategy/concepts/<direction>/`），每個主要視覺決定都要指到這裡的一條原則（P1…P5）；`reviewer` 的設計 rubric D2「與設計原則一致」也拿本檔評分。

- 輸入：`docs/strategy/messaging.md`（#165，`strategy-approved`）的定位句、`DM-1`～`DM-7`、`IT-1`～`IT-8` 與「語氣與用詞」；`docs/strategy/briefs/home.md` 的段落結構與 CTA，另兩份 brief（`digirunner.md`、`finance.md`）；`docs/strategy/competitors.md` 與 `docs/strategy/competitors/*.png`；現有設計系統（`design-system` skill、`src/styles/tokens.css`、`docs/design/motion.md`、ADR 0003、`docs/design/brand-assets.md`）
- 原則限制「傳達什麼」，不規定唯一的樣式。每條原則最後一列寫三個方向可以在哪裡不同；亮色或深色、有沒有 3D、用不用插圖，都不是原則決定的事
- 事實寫成反引號包住的 `fact:` 加事實 id，只用 `docs/strategy/facts.yaml` 裡 `locale: zh-TW`、`status: confirmed` 的條目。本檔不寫文案；原型的文字照 brief 與 messaging，缺的標為待補

## P1 第一屏用文字說出服務對象與做的事，影像只能幫腔

依據：messaging「定位」（替金融與政府，把 API、資料與 AI 安全接進既有系統）與「定位句的依據」第 2 列；`competitors.md`「比較」表的「定位說法」列（四家第一屏都沒寫服務對象，SYSTEX 的 h1 是空的、Syscom 的文字做在 banner 圖裡）；`briefs/home.md` 第 1 段（h1 寫定位句，說明第一句以「昕力資訊（TPIsoftware）」開頭，次要動作是「依產業看方案」）。rubric D1 要求只看第一屏就說得出公司做什麼、給誰。

會怎麼呈現：

| 面向 | 做法 |
|---|---|
| 版面 | h1（定位句）是第一屏面積最大、最先被讀到的元素。375 與 1280 寬的第一屏都看得到 h1、說明第一句、主要 CTA，以及「金融」「政府」兩個產業名稱（次要動作或產業標記）。產業名稱是可點的入口，不是裝飾字 |
| 字體 | h1 用 `--font-size-h1` 以上的字級與系統中文字，字重足以在影像上獨立成立；說明用內文字級，40–60 字（brief 第 1 段）在 1280 寬維持 2–3 行，不拉成一整行 |
| 色彩 | 文字與背後最不利像素的對比照 WCAG 2.2 AA；文字側的背景由版面讓出，不靠加深遮罩硬撐（`design-system`「影像」） |
| 影像 | 影像、3D 或圖解放在文字旁或文字之後，換掉它第一屏的意思不變。影像表達的是 P3 的「接進既有系統」，不是一般的科技感 |
| 動態 | h1 與 hero 靜態圖不做進場動畫（LCP，`design-system`「動態」）；第一屏的動態不能延後文字出現 |

不會怎麼呈現：

- 只有一句氛圍短標配全幅影片或發光物件（SYSTEX 的「萬物皆數」加晶片方塊，`competitors/systex-1280.png`）。現行 hero 的疊層玻璃板（`src/assets/design/hero-modular-stack.webp`）和 SYSTEX 的發光方塊同屬深色科技物件，換掉 logo 後不容易分辨；保留 3D 的方向要讓文字與產業入口承擔辨識度，不能讓物件承擔
- 輪播 banner、把標題做在圖片裡（Syscom），或 375 寬時 h1 被裁切、被推出第一屏
- h1 放公司名或口號（GSS 的 h1 是英文公司名）。品牌詞由 title 與說明第一句承擔（brief「取捨」第 3 項）
- 第一屏出現「數位轉型」「頂尖」「賦能」等 messaging「本站不用的字」當主視覺文字

三個方向可以不同的地方：hero 的構圖（文字左右分欄、文字壓在場景上、純文字加下方圖解）、影像的種類、深色或亮色 surface。

## P2 證據長得像紀錄：事實原文、條件與出處擺在一起，跟表述分開

依據：messaging 開頭的規則（主張裡不放數字、客戶名或最高級說法，這些只能出現在引用的事實裡）與「語氣」（數字連同事實裡的條件一起寫，例如 `fact:digirunner-tps` 的「取決於不同環境的配置」、`fact:digirunner-cloud-trial-terms` 的費用說明）；`DM-2`（成果寫得出來）、`DM-6`（穩定度看得到）；`competitors.md`「不適合本站」的數字動畫（FPT 在 script 沒載入時只剩「1+」）與「本站缺」第 2 項（GSS 的具名客戶加受訪者職稱比 logo 牆說得多）。rubric D5 評證據是否容易看到、讓人信任。

會怎麼呈現：

| 面向 | 做法 |
|---|---|
| 版面 | 事實用固定的「紀錄」格式，全頁一致。案例寫成「作業 → 成果 → 連結」三格（brief 第 3 段的 `fact:smartclaim-result`、`fact:smartfilling-result`、`fact:fraud-platform-result`）；穩定度寫成一列年份或項目加原文（brief 第 7 段的 `fact:company-founded`、`fact:company-milestone-2008-finance`、`fact:company-subsidiaries-sg-vn`、`fact:cert-iso27001-product-platform`、`fact:company-google-cloud-partner`）。條件小字緊貼在數字下方，不放到註腳 |
| 字體 | 事實與表述在字體上有固定差異，例如事實的標籤或年份用 `--font-mono`（現有規則：mono 只用在編號、eyebrow、資料標籤），表述用 `--font-sans`。成果原文照引，不改寫成更強的短句 |
| 色彩 | 證據區塊用中性底色與細框線，品牌色只標出「這是事實」的標記（例如左側色條或資料標籤），不把成果數字塗成大面積漸層 |
| 影像 | 具名客戶以文字呈現客戶名稱（`fact:digirunner-case-taishin`、`fact:digirunner-case-taipei-city` 這類具名案例），合作夥伴與客戶分開標示（`competitors.md`「本站缺」第 2 項）。證言若採用（見「待確認」第 3 項），寫出說話人與原文，不配圖庫人像 |
| 動態 | 數字直接輸出在 HTML，不做數字跳動或計數動畫（brief 第 7 段）。證據可以用 `Reveal` 進場，減少動態時直接顯示 |

不會怎麼呈現：

- 把一個百分比放大成整屏的主視覺而省略事實原文的其他部分，或拿掉條件（例如只寫 TPS 數字、不寫「取決於不同環境的配置」）
- 數字動畫、輪播的客戶 logo 牆、沒有標示是客戶還是原廠的 logo 牆（SYSTEX）
- 用裝飾圖、icon 或形容詞大標取代證據（「值得信賴的夥伴」這類標題底下沒有事實）
- 把 `to_confirm` 的獎項、員工數、專案數放進畫面（messaging「缺少證據的主張」第 2、3 項）；原型裡也不放假數字佔位，缺的寫「待補」

三個方向可以不同的地方：紀錄格式的長相（表格、時間軸、卡片、頁邊註記）、證據段在頁面上的位置與面積。

## P3 畫的是「接進既有系統」，不是「全新的未來」

依據：定位句「把 API、資料與 AI 安全接進既有系統」；`IT-4`（接上既有系統，不必先汰換）、`IT-6`（AI 流量和 API 走同一道 Gateway）、`DM-4`（產品與導入由同一家負責）；`briefs/home.md` 第 4 段（每個產品家族寫解決什麼問題）與第 6 段。`competitors.md` 的「視覺語言」列：四家用的是晶片、手指、光流、漸層這類和業務無關的科技圖。

會怎麼呈現：

| 面向 | 做法 |
|---|---|
| 版面 | 產品家族依「要解決的問題」排（接既有系統與 AI 串接、AI 模型、碳盤查、身分驗證，brief 第 4 段），不依內部組織排。能表達接點的地方用「既有系統 ↔ 昕力的產品 ↔ 新的服務」這種左中右或上中下的關係 |
| 字體 | 圖解裡的標籤用真實的系統類別名稱（核心系統、大型主機、WAF、AI 模型，取自 `fact:digilism-protocol-integration`、`fact:digirunner-nginx-waf` 等事實的用詞），產品名照 messaging「產品與公司名寫法」 |
| 色彩 | 既有系統用中性色，昕力的產品與接點用品牌色，讓「誰接了什麼」一眼分得出來。能量漸層（`--gradient-energy`）只畫在連線與接點上（現有規則：光標示資料與互動） |
| 影像 | 影像要能讀成「層」「接點」「管線」「閘道」：3D 方塊重組成模組、2D 的架構圖解、或產品介面的局部都可以，前提是畫得出接進來的關係。現有的抽象影像規範（`design-system`「影像」：不放文字、數字、人物、真實產品）若要放寬給產品介面截圖，由方向說明寫出代價 |
| 動態 | 動態表達因果：捲動時連線接上、模組歸位、流量通過閘道。動態停下來的畫面（減少動態時）仍然看得出接點 |

不會怎麼呈現：

- 和做的事無關的科技圖：晶片、手指觸控、地球網路、光流（GSS、SYSTEX、Syscom 的主視覺）
- 「全部推倒重來」的意象：空白的未來城市、從零長出的新平台，或只畫昕力的產品、沒有既有系統的圖
- AI 擬人化：機器人、發光大腦、對話泡泡當主視覺（AI 對話視窗本站也不做，`competitors.md`「不適合本站」）
- 把產品家族做成同一種卡片加 icon 的格子，讀不出各自解決什麼問題

三個方向可以不同的地方：用 3D、2D 圖解或產品介面表達接點；接點畫在 hero 還是畫在產品家族段。

## P4 克制與可預期：光與動態只標示資料、狀態與下一步

依據：`DM-1`（規範要求做在產品裡）、`DM-3`（資料、權限與用量都在掌控內）、`IT-5`（使用軌跡都看得到）；messaging「語氣」（寫產品做的事，不寫形容詞）；決策者來首頁「評估導入風險、長期合作風險」（`briefs/home.md` 第 6、7 段）。受眾是受監管的金融與公部門，畫面本身要像一個「受控」的系統。現有設計方向也已規定光只用在線條、外框、焦點與 hover（`design-system`「設計方向」）。

會怎麼呈現：

| 面向 | 做法 |
|---|---|
| 版面 | 一套格線貫穿全頁，對齊清楚；聯絡業務的入口位置固定且可預期（hero、頁尾，加上 header 或固定入口其中之一），讀者不用找 |
| 字體 | 層級少而明確：display 或 h1、h2、內文、資料標籤。不靠字體種類變化製造氣氛 |
| 色彩 | 大面積是中性色（`--ink-*` 或白），品牌紫、品紅、橘只用在連結、按鈕、資料標記、接點與焦點。能量漸層不當文字底色，也不鋪滿整個區塊 |
| 影像 | 影像數量少，每張都有任務（P3 的接點或 P1 的幫腔）；同一頁不混用多種影像風格 |
| 動態 | 動態只表達狀態與因果：hover、focus、展開、捲動時的接上與歸位。循環動畫只放在一處以內，偏好減少動態時整頁停在完成狀態（`motion.md`） |

不會怎麼呈現：

- 自動播放的輪播、自動切換的頁籤、背景影片
- 大面積霓虹光暈、粒子特效、滑鼠跟隨的發光，或讓文字閃爍、跳動的效果
- 浮動聊天視窗、會遮住內容的彈出層（`competitors.md`「不適合本站」）
- 需要猜的互動：只有 hover 才看得到的關鍵資訊、沒有文字標籤的 icon 按鈕

三個方向可以不同的地方：中性色的深淺（深色場景或亮色紙面）、品牌色的比例、固定聯絡入口的形式（header 按鈕、底部固定列或不加）。

## P5 版面照讀者的判斷順序分輕重，每段回答一個問題

依據：`briefs/home.md`「段落結構」的排序理由（先確認「是不是為我做」：hero、產業；再看「做得到嗎」：案例、產品、OrientAI；最後看「找這家安不安心」：導入、穩定度，再聯絡）與「受眾與任務」（兩次捲動內找到自己的產業入口與一則有成果的案例）。`competitors.md`「不適合本站」：FPT 約 11,100 px 的長首頁；`competitors.md`「首頁結構」：GSS、SYSTEX 每段用同一種卡片格。rubric D3 與 D4 評視覺層級與節奏。

會怎麼呈現：

| 面向 | 做法 |
|---|---|
| 版面 | 8 段各自有不同的版型密度：hero、產業入口、案例三段的視覺權重最高；產品家族是可掃讀的索引；穩定度是緊湊的紀錄列；聯絡是收束。375 寬重新安排，不是縮小版：產業入口與第一則案例在兩次捲動內出現 |
| 字體 | 每段的標題寫這段回答的問題的答案（文案由 brief 決定），字級依段落重要性分級，不是每段都用同一級 h2 樣式加同樣的留白 |
| 色彩 | 用底色或分隔標出三組判斷（是不是為我做、做得到嗎、安不安心），讓長頁面有節奏，不是每段交替黑白 |
| 影像 | 影像集中在 hero 與 P3 的接點，不在每段都放一張封面圖 |
| 動態 | 進場動態只用在每段的主要元素，不讓每張卡片都依序飛入 |

不會怎麼呈現：

- 每段都是「標題 + 三或四張等大卡片」的重複格子，讀者分不出哪段重要
- 為了填版面加回 brief 已刪的段落（最新文章與新聞），或加 brief 沒有的段落（雇主品牌、新聞輪播）
- 375 寬時把桌機的多欄直接堆成一長串，產業入口被推到第四、五屏之後

三個方向可以不同的地方：段落的分組方式、各段的版型（全寬、雙欄、索引表）、頁面總長度。

## 原則與現有限制

第 2 階段的方向說明要寫出放寬哪些現有限制與代價（`design-concept` skill 第 3 節第 3 步）。下表列出原則最可能碰到的限制，不代表要放寬。

| 現有限制 | 來源 | 可能碰到的原則 |
|---|---|---|
| 不載中文 webfont，`@font-face` 只有 Inter 與 JetBrains Mono 的 latin、vietnamese、greek | `design-system`「Token 分層」、`scripts/design/font-subsets.mjs` | P1、P2：中文標題與事實標籤只能用系統字表現層級。改用中文 webfont 的方向要寫出字型檔大小與首次繪製的代價 |
| 每頁初始 JS 6 KB、延後載入 140 KB（gzip） | `motion.md`「效能預算」、`scripts/design/scene-budget.mjs` | P3：表達接點的互動圖解若要 JS，要放進預算 |
| 真 3D 只在首頁與部分 offering 頁的 hero 與功能章節，靜態圖是 LCP | ADR 0003、`motion.md`「3D 的使用範圍」 | P1、P3：3D 物件不能承擔第一屏的辨識度；拿掉 3D 的方向省下延後載入的 JS，但要另找表達接點的方式 |
| 色彩只用 `tokens.css` 的 token，品牌三色沿用現站，橘 500 只當裝飾 | `design-system`「規則」「Token 分層」、`docs/design/brand-assets.md`「品牌色」 | P2、P4：事實標記與接點的配色要在兩個 surface 都過對比 |
| 影像只用抽象 3D 渲染，不放文字、數字、人物、真實產品 | `design-system`「影像」 | P3：用產品介面截圖或架構圖解表達接點時要放寬 |
