## 評審：switchboard

評審日期 2026-11-01，由新的 `reviewer` 依 `site-review` 評分。評審只讀了 `index.html`、四張截圖、依據文件、兩份 rubric 與競品截圖，沒有讀本目錄的 `README.md`、其他方向與任何 review；另外自己用 Playwright 在 1280 寬捲到 y=1500 與 y=2600 截圖看 sticky 側欄（截圖不在 repo）。設計概念階段不判斷通過與否，分數只供選方向。

第一印象：只看第一屏就知道是誰、做什麼。h1「替金融與政府，把 API 與 AI 安全接進既有系統」占了第一屏最大的面積，右邊是「金融」「政府與公部門」兩個產業入口，下緣露出「既有系統 → 昕力的產品 → 新的服務」的接線圖。四家競品第一屏都是科技影像，沒寫服務對象，這頁換掉 logo 也不會跟它們搞混。375 寬時 h1、說明、兩個 CTA 和兩個產業都在第一屏內。

### 設計：平均 4.3

| 項目 | 分數 | 理由 |
|---|---|---|
| D1 第一屏的辨識度 | 5 | 只看 `shot-1280-first.png` 與 `shot-375-first.png` 就說得出來：替金融與政府，把 API 與 AI 接進既有系統，是研發並導入自有軟體的公司。第一屏沒有影像，辨識度由文字和產業入口撐起來。下緣的接線圖寫的是「核心銀行系統、大型主機、既有的 WAF」，這是業務關係，不是 SYSTEX、GSS、Syscom、FPT 那種晶片、手指、光流、漸層 |
| D2 與設計原則一致 | 4 | 大部分決定對得到原則。P1：h1 最大，產業名稱可點，沒有進場動畫。P3：hero 接線圖和產品家族的「輸入 → 產品 → 輸出」小圖，既有系統用中性框，昕力的產品用紫框，連線是橘色。P4：大面積是中性色；sticky 側欄裡的「聯絡業務」是固定入口；動態只有用 scroll-timeline 畫出連線，而且有 `prefers-reduced-motion`。P5：用白、深、灰三種底色加側欄的「是不是為您做／做得到嗎／安不安心」分出三組判斷。不一致的地方是 P2 要求「紀錄格式全頁一致」，但頁面上至少有五種：02 與 06 是左色條加標籤（產品功能、導入服務），03 是接線加圓點、沒有標籤，05 的條列只有色條、沒有標籤，05 另有一張 Q&A 卡，07 是時間軸。另外原型載入了 Noto Sans TC 中文 webfont，碰到「原則與現有限制」第 1 列（不載中文 webfont），要另外交代字型檔大小與首次繪製的代價 |
| D3 視覺層級 | 4 | 每段都有明確的 h2 焦點，閱讀順序和 brief 一致。有三處互相搶焦點：(1) 1280 寬的深色段（03–05），sticky 側欄是白底卡片，成為畫面最亮的東西，視線先被它拉走；(2) 04 產品家族有四張接線小圖，看起來比 03 案例的列表更重，但 brief 與 P5 要求案例的權重高於產品索引；(3) 07 的證言字級比時間軸大很多，「穩定度紀錄」的主角變成一段口語證言。另外 hero 右欄的產業入口上方空了約 270 px，在 1280 寬看起來像版面沒排滿 |
| D4 版面與節奏 | 4 | 各段的密度有變化：案例是橫列，家族是 2×2，OrientAI 左右分欄，服務是清單，紀錄是時間軸。間距一致，底色分組也有節奏。不足的地方：03–05 在 1280 寬連續約 1,900 px 都是深底，三段標題的樣式一樣，捲動時有點單調。「產品總覽」之後、05 之前的空白偏大；05 左欄條列下方也有一大塊空白 |
| D5 證據的呈現 | 4 | 證據的結構對了：事實照原文放在主張旁邊，數字直接寫在 HTML 裡、沒有動畫；客戶以文字具名，證言寫出說話人與職稱（Dora 徐靜婷，新光銀行），沒有配人像；年份用 mono。抽查 20 筆事實，全部和 `facts.yaml` 的 quote 一致。扣分的原因是格式不統一：03 的案例成果沒有「成果」這類標籤，05 的條列也沒標出是事實，讀者分不出哪些是事實原文、哪些是表述，和 02、06 的做法不同 |
| D6 窄螢幕 | 5 | 375 寬是重新排過的，不是縮小版：hero 的 h1、說明、兩個 CTA、兩個產業入口都在第一屏；接線圖改成上中下三層的直式版本，另外畫了一張；側欄拿掉；時間軸改成直式；案例改成「標題 → 色條成果 → 連結」。第一則案例大約在兩次捲動內出現，符合 brief。沒有橫向捲動。小問題：產品家族小圖的「GreenSwift」文字貼到框邊，1280 與 375 都一樣 |

要改的地方：無（沒有低於 4 的項目）。

供參考，不影響分數：

- D2、D5：事實的紀錄格式收斂成一種，讓讀者一眼分得出事實原文與表述。03 案例成果、05 條列都要有和 02、06 一樣的標記
- D3：深色段裡的 sticky 側欄不要成為畫面最亮的元素；03 案例的視覺權重應該高於 04 產品家族

### 文案與行銷：平均 4.3

| 項目 | 分數 | 理由 |
|---|---|---|
| C1 定位清楚 | 5 | h1 說了對象（金融與政府）和做的事（把 API 與 AI 安全接進既有系統）。說明句以「昕力資訊（TPIsoftware）研發並導入自有軟體」開頭，再說差異：「規範要求直接做在產品功能裡，核心系統不必先汰換」。和 messaging 的定位句一致，h1 也沒有品牌詞，符合 brief「取捨」第 3 項 |
| C2 對受眾的價值 | 4 | 每段都對到受眾的任務或顧慮。02 寫「專案不必從零設計合規架構」，06 寫「您不必在產品原廠與導入廠商之間協調」，07 的標題「合作之前，先看這家公司的紀錄」，都是用讀者的語言寫風險。04 的家族句依問題來寫（「接上核心系統與大型主機」）。不足的是 05 OrientAI 下面的四點是功能片段（「Token 成本控管」），沒有寫成決策者在意的掌控結果；說明句（「資料不交給外部……」）寫得到位，但條列沒有跟上 |
| C3 證據支撐 | 4 | 02、03、05、06、07 的主張旁都有事實。抽查的 20 筆全部是 `confirmed`，原文一致，包括 smartclaim-result、smartfilling-result、fraud-platform-result、digirunner-open-banking-fsc、digirunner-ndc-spec、orientai-* 五筆、testimonial-shin-kong-bank、時間軸六筆、company-offerings、aiso-onboarding。分布不均：04 的四個家族句都沒有放證據，brief 第 4 段列的 `digilism-protocol-integration`、`greenswift-scope` 等事實在畫面上看不到。06 的「導入服務」引用 `aiso-onboarding`，但這筆原本講的是 AISO 的服務，放在全公司的主張下又沒標出 AISO，事實的範圍被放大了 |
| C4 CTA 與轉換路徑 | 4 | 主要轉換「聯絡業務」出現在 header、hero、sticky 側欄（1280）和頁尾段。頁尾段寫清楚了按下去會發生什麼：「昕力業務會與您聯繫，安排需求訪談或產品展示」，回覆時間標成待補，沒有亂填。次要 CTA 照 brief 都有：看所有成功案例、認識 OrientAI、產品總覽、關於昕力。不足的地方：hero 右欄的「金融」「政府與公部門」都連到 `#industries`，和「依產業看方案」按鈕是同一個目的地，看起來是兩個入口，實際只有一個；hero 和側欄的「聯絡業務」連到頁尾段，不是聯絡頁，多了一步 |
| C5 符合 brief | 5 | brief 的 8 段照順序都做到。02 只列金融與政府，03 是三則 AI 案例並連到兩個解決方案頁和列表，04 是四個家族，產品連結帶類別詞（「digiRunner API 管理平台」），GadoSecurity 標題不加連結，保留產品總覽。05 用了 brief 列的五筆 OrientAI 事實。06 的六張服務卡和節點名一致（含「AISO 主權 AI」）。07 是六筆紀錄加一則證言，brief「待確認」第 1 項允許加。08 的標題寫下一步。hero 的接線圖屬於第 1 段的影像，不算多出來的段落。字數大致都在預估範圍內 |
| C6 語氣與文字品質 | 4 | 語氣和 messaging 一致：寫做的事，不寫形容詞；用「您」；沒有「賦能、頂尖、領先」；產品名大小寫都正確（DigiLism、digiRunner、SysTalk.ai、ESGswift、gadoDIDO、群聯 aiDAPTIV）。有三處生硬：(1) 05 條列照抄現站的原文碎片，空格取代了標點（「AI Agent 統一管控與授權標準化 Token 用量監控與資源配置最佳化 消除影子 AI……」），「Token 成本控管」單獨一行，讀起來像壞掉的文字；(2) 06 選用的事實「……再到全方位軟體解決方案」本身就是空話，撐不住 DM-4；(3) 每段的 eyebrow「是不是為您做／做得到嗎／安不安心」是 brief 內部的分組用語，直接給 CIO 看，「安不安心」顯得口語 |

要改的地方：無（沒有低於 4 的項目）。

- C6：05 改挑能完整閱讀的事實，或改變呈現方式，讓原文碎片不要直接成為條列；06 換掉「全方位軟體解決方案」這筆
