# 第三輪的三個方向（#166）

本檔定義設計概念第三輪的三個首頁方向，給三個 agent 各自建原型（`docs/strategy/concepts/<id>/index.html`）。方向由 `design-director` 以軟體、技術公司的網站為參考定義，不用 `taste-skill` 的 `draw.mjs` 發牌（使用者 2026-11-01 決定，`.claude/skills/design-concept/SKILL.md`「用 `taste-skill` 檢查原型」）。

- 依據：`docs/strategy/design-principles.md` 的 P1–P5（第三輪版）、`docs/strategy/briefs/home.md` 的 8 段、`docs/strategy/concepts/copy-deck.md` 的文字、`docs/strategy/competitors.md`
- 第一輪 switchboard（設計 4.3，`git show c6613f4:docs/strategy/concepts/switchboard/review.md`）是目前最高分，本輪三個方向都保留它做對的事：第一屏只靠文字就說清楚替誰做什麼、影像畫的是接點、底色分出三組判斷
- 第二輪五個方向（設計 3.3–3.7，`git show a631a4b:docs/strategy/concepts/<direction>/review.md`）的扣分點，整理在「三個方向共用的規則」，三個原型都要照做

## 三個方向共用的規則

這些規則來自第二輪評審的扣分，三個原型都照做，`reviewer` 也拿它對照。

### 色彩的意思全頁固定

三個方向用同一套「顏色代表什麼」，只換底色與比例。品牌色完整使用（`design-principles.md` P3、P4「色彩」）：

| 代表 | 顏色 | 說明 |
|---|---|---|
| 既有系統（核心銀行系統、大型主機、既有的 WAF、ESB） | 中性色（`--ink-*`） | 不是昕力的東西，不塗品牌色 |
| 昕力的產品與主要動作（digiRunner、DigiLism、OrientAI、「聯絡業務」按鈕） | 紫（`--purple-*`） | 紫也是 logo 的顏色，讀者會把紫讀成「昕力」 |
| 接點與流量（API 請求、資料轉換、接線） | 橘（`--orange-*`） | 只畫接點，不當段落底色（`layer-fields` 的淡橘章是 `--orange-50`，近乎中性，見該方向） |
| AI 的流量與 AI 產品（AI Gateway、模型、Agent） | 品紅（`--magenta-*`） | 只標 AI，不用在其他地方 |

- 不用漸層、光暈、陰影；顏色都是平塗
- 文字、按鈕與圖上必要的線條都要過 WCAG AA（文字 4.5:1、大字與圖形 3:1）。每個方向的「色彩」表寫了實際用的組合與對比值，原型不另外加組合；要加就先算對比
- 對比值用 WCAG 2.x 相對亮度公式從 `src/styles/tokens.css` 的色碼算出（本檔撰寫時以 node 計算）

### 介面片段

- 根元素加 `data-ui`，片段旁或片段內有「示意」兩個字，讀者看得出這不是產品截圖（`design-principles.md`「待確認」第 4 項）
- 片段裡的字只有三種：事實原文（`docs/strategy/facts.yaml` 的 zh-TW `confirmed`，可以拆成多列，字不改）、事實裡出現過的系統或產品名稱、本檔每個片段列出的介面用語（例如「通過」「轉送」）。不放數字、時間、筆數、ID、使用者名稱、百分比，事實原文裡的除外
- 每則事實全頁只顯示一次（`copy-deck.md`「第三輪修正」第 4 項）。片段用的事實已經在同一段的文字裡照引時，片段只放事實裡的名稱當標籤（例如「Token 用量」「權限」「核心銀行系統」），不再重複整句原文
- 片段的字級只用頁面五種字級裡的 small 與 body，不另外指定字級（第二輪 borrowed-category 因片段另訂字級被扣 D2）
- 片段不超出版心、不被 header 或視窗邊緣裁掉（第二輪 product-performs 的片段右緣被裁、hero 片段被 header 切半）；375 寬時片段改成直式或精簡版，不縮放整塊
- 片段內的控制項可以有 1px 框線與小圓角（`data-ui` 內照產品慣例），但沒有陰影
- 片段的亮度與面積不能超過 h1：深色頁的片段底色比頁面亮一階就好，不用白底

### 字級與字體

- 全頁最多五種字級，介面片段、按鈕、頁尾都算在內，在 CSS 定義成五個變數，其他地方只引用變數，不寫 `vw` 或另一組 `clamp()`
- 中文用系統字：`"PingFang TC", "Microsoft JhengHei", "Noto Sans TC", sans-serif`，排在拉丁 webfont 之後。不載中文 webfont
- 拉丁 webfont 用 npm 上 fontsource 的套件，原型用 `npm pack` 下載到 `/tmp`，只複製 latin subset 的 woff2 與授權檔到方向目錄（`design-concept` skill 的衝突表最後一列）
- 年份與數字用 `font-variant-numeric: tabular-nums`，不用等寬字

### 375 寬的距離預算

brief 要求兩次捲動內（375×812 的 1624px 內）看到產業入口與一則有成果的案例。第二輪五個方向的第一則案例都落在 2,980–3,500px，主因是第 2 段太長、hero 影像太高。三個方向都照下表的上限排，每個方向的「375 寬」一節另寫自己的分配：

| 位置 | 上限（y，px） |
|---|---|
| hero 結束（h1、說明句、兩個動作、精簡影像都在內） | 760 |
| 第 2 段產業入口的 h2 | 840 |
| 第 3 段案例的 h2 | 1,300 |
| 第一則案例的成果原文出現 | 1,560 |

- 第 2 段照 `copy-deck.md` 第三輪的長度（約 130 字），不加事實、不加片段
- hero 不再另列產業入口清單：h1 已有「金融與政府」，次要動作「依產業看方案」連到第 2 段。第一輪 switchboard 在 hero 與第 2 段重複列產業被扣 D6
- 原型完成後量 375 寬的實際位置，寫在方向的 README

### 版面

- 一組左右相等的外側邊距（1280 寬 48px、375 寬 20px），全頁同一套 12 欄格線
- 沒有超過半屏的空白，一段的文字在左半時右半要有這段的片段、圖、清單或第二欄（第二輪 product-performs、colour-chapters 被扣 D4）
- 段距 1280 寬 128–160px、375 寬 64–80px，段內的間距明顯小於段距
- 相鄰兩段的版型不同；每段只有一個焦點，案例段的權重高於產品家族段（第一輪 switchboard、ledger 被扣 D3）
- 事實全頁用同一種紀錄格式：同一個位置（主張下方）、同一個字級（body）、同一個顏色標記（每個方向寫明），不畫框、不加左側色條（第一輪 switchboard 有五種格式被扣 D2、D5）
- header：wordmark、4 個文字連結（產業、產品、成功案例、關於昕力）、「聯絡業務」按鈕；375 寬是 wordmark、「選單」文字按鈕、「聯絡業務」。header 不固定，不蓋到內容
- 不用 eyebrow、編號、細線、等寬字、玻璃、陰影、漸層（taste-skill house rules）

### 動態

- 每段進場：標題、文字、圖依序錯開 60–90ms，上移 16–24px 加淡入，只觸發一次，只動 `transform` 與 `opacity`。script 沒載入時內容照常顯示
- 每個按鈕、連結、頁籤有 hover、press、focus 回饋，focus 框看得到
- h1 與說明句不做進場動畫（LCP，P1「動態」）
- `prefers-reduced-motion: reduce` 時拿掉位移與逐列出現，整頁停在完成狀態
- 不用 GSAP、Lenis；動態用 CSS 與少量原生 JS，原型的 JS 控制在 6 KB（gzip）以內，符合現有的初始 JS 預算（`docs/design/motion.md`）

## 方向 1：`gateway-console`

### 一句話

深色主控台：每一段都用一塊 digiRunner 或 OrientAI 的介面片段，示範請求怎麼通過規範、接進既有系統。

像 API 與 AI 閘道、開發者平台、地端基礎設施廠商的網站。這類網站賣的是「控制」，最有說服力的影像是產品自己的畫面；昕力的主力產品（digiRunner、OrientAI）正是這類產品，決策者也最在意資料與權限是否受控（`DM-3`）。
