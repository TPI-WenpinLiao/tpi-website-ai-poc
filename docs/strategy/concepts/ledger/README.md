# 方向 ledger：紀錄簿

首頁讀起來像一份有附註的紀錄。亮色紙面、沒有影像，標題用中文襯線字（Noto Serif TC），表述放在主欄，事實原文放在右側的頁邊註記，每則註記都有標籤與出處。第一屏只有文字：定位句、說明、兩個按鈕，以及「金融」「政府與公部門」兩列產業索引。接點只在第 4 段用一張編號圖解（圖 1）說明。證據靠版面上的固定位置與格式取得信任，不靠影像。

- 原型：`index.html`（從 `file://` 直接打開，不連外部網址）
- 截圖：`shot-375.png`、`shot-375-first.png`、`shot-1280.png`、`shot-1280-first.png`（`node scripts/strategy/concept-shots.mjs --only ledger`）

| 面向 | 決定 | 原則 |
|---|---|---|

| 版面 | 第一屏沒有影像，h1 是面積最大的元素；hero 底下直接列出「金融」「政府與公部門」兩列可點的產業索引 | P1、P5 |
| 版面 | 案例寫成「作業 → 成果（案例原文）→ 連結」的表格，成果欄用橘色左線標成事實；公司紀錄是年份欄加原文的表格 | P2 |
| 版面 | 每段以一條粗線加段落編號開始，8 段各有不同密度：產業是兩欄、案例是表格、產品是索引列、紀錄是緊湊表格 | P5 |
| 字體 | 標題（h1–h3、產業索引）用 Noto Serif TC 700，內文用系統黑體，資料標籤、年份、段落編號用 JetBrains Mono。三種字體各有固定任務，事實與表述在字體上就分得出來 | P2、P4 |

| 動態 | 沒有進場動畫或捲動動畫，只有連結顏色的變化與頁內錨點的平滑捲動；減少動態時兩者都關掉 | P4 |

| 面向 | ledger | scene | switchboard |

## 放寬的限制

| 限制 | 處理 |
|---|---|
| 中文 webfont | 放寬：只給標題用 Noto Serif TC 700，內文維持系統字。依 fontsource 的 unicode-range 切片，只複製本頁標題實際用到的切片：173 個字元落在 13 個 woff2，共 594.9 KB（`assets/fonts/`）。另有 Inter 與 JetBrains Mono 的 latin 切片 47 KB、39 KB，和 production 相同。代價：本機用 Lighthouse 行動版的網路條件（150 ms RTT、1.6 Mbps、CPU 4 倍降速）量 3 次取中位數，FCP 524 ms（用備用字先畫出），最後一個 woff2 在 4074 ms 才下載完，標題會在這時換字，字寬不同會造成版面位移。宋體的切片比黑體大（每片約 45 KB）。內容一變，用到的切片就會變，`scripts/design/font-subsets.mjs` 要改成也檢查中文切片 |
| JS 預算（初始 6 KB／延後 140 KB gzip） | 照現有，而且更少：原型沒有任何 `<script>`。拿掉 3D 後首頁不載入延後的 three.js chunk（ADR 0003 量到 runtime 130 KB gzip） |
| 3D | 放寬：首頁不用 3D。`Scene3D`、`modular-stack` 場景與 hero 的 `Backdrop` 都不出現在首頁；`design-system`「設計方向」的「敘事頁放在深色 surface、底下是 3D 捲動場景」要改寫 |
| 色彩 token | 照現有：只用 `tokens.css` 亮色 surface 的值（ink、purple-700/800/900、orange-700）。用法上收窄：品牌色不做大面積，只有按鈕、連結與事實標記 |
| 影像規範 | 放寬：「抽象 3D 渲染，不放文字」改成允許含文字的架構圖解（圖 1）。圖解裡的文字只用事實庫的系統與產品名稱，不放數字。代價：圖解要隨產品調整而維護，橫式與直式兩份 SVG 要一起改 |

## 原型與 production 的差距

- 連結都是 `#`；header 只有五個主選單名稱，沒有 mega menu、語系切換、搜尋
- 樣式直接寫 token 的原始值（primitives），production 要改用語意 token 並通過 `npm run check:design`
- 事實照 `facts.yaml` 的 `text` 手打進 HTML，去掉了 U+200B；production 用 `fact('<id>')`
- 「出處」寫新站的頁面名稱（依 `docs/ia/page-map.csv` 把現站網址對到新節點）。production 要決定出處要不要做成連結
- 系統字在截圖環境是 WenQuanYi Zen Hei，不是 PingFang TC 或微軟正黑體；內文的實際樣子以這兩者為準
- 中文切片是對這一版文字算出來的（`/tmp` 的一次性 script，用 playwright 讀每個文字節點的計算後字體），文字改了要重算
- 對比用 axe-core（WCAG 2.1 AA）在 375、1280 寬檢查過，沒有違規；沒有跑 `scripts/design/contrast.mjs`、Lighthouse

## 待補

- 第 8 段：聯絡後多久回覆（`briefs/home.md`「待確認」第 4 項），頁面上標了「待補」
- 第 6 段的服務只有名稱，沒有說明句（brief 只寫名稱；要說明句時另寫表述）
- 第 1 段 `fact:company-industries` 的原文提到製造生產等其他產業，跟 hero 不點名製造業衝突，所以畫面上沒有引用；要不要在別處當註記，由製作階段決定
- 證言的出處目前寫「客戶證言」，新站的證言放在哪一頁還沒定
- hero 產業索引的副標（「開放銀行與金融檢查」「共通性 API 規範」）與圖 1 的方框文字是新寫的表述，要由人審
