## 評審：loud-flat-poster

評審日期 2026-11-01，由新的 `reviewer` 依 `site-review` 評分。評審沒有讀本目錄的 `README.md`、`sheet.md` 與其他方向；另外用 reduced motion 重截產品段與 OrientAI 段，確認裁切是版面本身而不是動畫中途（截圖不在 repo）。設計概念階段不判斷通過與否，分數只供選方向。

第一印象（只看 `shot-1280-first.png`、`shot-375-first.png`）：滿版黃底配一句超大黑字「金融與政府的系統接上 API 與 AI」，5 秒內就看得出來是替金融與政府做 API、AI 系統串接的軟體公司。四家競品的第一屏都是深色科技影片或光流漸層，這張和它們完全不同。中間那張 1876 年蒸汽印刷機的版畫說不出跟這家公司有什麼關係，但沒有壓到任何文字。1280 寬時 h1 兩行的字幾乎碰在一起（「府」與「接」之間），API 和 AI 用寬體拉丁字，跟中文的字寬差很多。

### 設計：平均 3.5

| 項目 | 分數 | 理由 |
|---|---|---|
| D1 第一屏的辨識度 | 5 | 兩個寬度的第一屏都看得到四樣東西：兩行的 h1（做什麼、為誰）、緊接的說明句（以「昕力資訊（TPIsoftware）」開頭、帶出「規範要求直接做在產品功能裡」）、紫色「聯絡業務」與「依產業看方案」，以及右欄（375 寬時在圖下方）一則加引號的 digiRunner 金管會事實。黃色平塗大字的海報構圖跟 `competitors/*.png` 的深色晶片、手指、光流、橘紫漸層都不一樣，拿掉 logo 也不會跟競品搞混 |
| D2 與設計原則一致 | 3 | 對得上的地方：P1 全部做到（h1 兩行、沒有 eyebrow、圖在文字旁邊）；P2 的「事實加引號加出處」紀錄格式（`#industries` 的 `.band`、`#about` 的 `.records` 用年份當 dt）；品牌紫只用在 logo 與主要 CTA；數字直接寫在 HTML。違反或說不通的地方：(1) P4「一個底色、一個文字色、一個 accent」：黃、珊瑚紅、綠、黑、米白五種平塗色在同一列並排（`.poster-row`、產品 bento、`#services` 四欄），不是「一個 accent」，比較像五種 accent 輪流用。(2) P4「全頁最多五種字級」：實際有 display、head、lead、sub、body、small，加上 `.big-switch` 的 11vh、wordmark 的 26vw，以及 bento 放大片段的 30–60px，遠超過五種。(3) P3：圖都是 19 世紀的版畫與老照片（印刷機、軍醫院、帳簿、銀行大廳、台灣山徑），沒有一張畫出「接進既有系統」；`#about` 的山徑照片跟這段內容無關，算裝飾。真正畫出接點的只有 DigiLism 那塊的「核心銀行系統｜DigiLism｜ESB」，偏偏被裁掉了。(4) h1 的「API」「AI」換成寬體拉丁字，看起來像被特別強調的詞，碰到 P1 的 no styled accent word。(5) 介面片段與 `.band` 用 1px 細框，跟 P2 的 no thin rules 衝突 |
| D3 視覺層級 | 3 | hero 的焦點很清楚，只有 h1。往下各段有東西搶焦點：`#industries` 四張等大的彩色海報（開放銀行、金融檢查、共通性 API 規範、通訊機制）一樣重，底下 tab 區又把同樣的事實引一次，讀者不知道該先看哪裡。`#cases` 每則左邊是約 700px 寬的老照片，成果原文卻是右下角內文大小的 blockquote，第一眼落在跟案例無關的醫院病房照，不是在成果上。`#products` 被裁掉的放大字（「無密碼」上緣被切、「異常」右邊被切、「AI Gateway」的「MCP」與「E」被切）比產品名更搶眼。`#orientai` 右側巨大的「離線運行 開」開關被右緣切掉，搶走 h2 的位置。`#services` 的 h2「產品和導入，同一家負責」跟四欄步驟標題一樣大 |
| D4 版面與節奏 | 3 | 節奏有變化：段落用整片色塊分開，密度在紀錄列、bento、四欄步驟、年份紀錄之間切換，長頁面不單調。但間距不一致，有的地方看起來像沒排完：1280 寬 `#cases` 每則的右欄上半部空著，介面片段沉在底部，半個畫面是空的（違反 house rule「一段的文字擠在一側、另一半螢幕空著」）；`#industries` 的 h2 色帶上下各留約 120px 的空紅；產品 bento 的放大片段溢出格子邊界，左上一塊米白空格什麼都沒有（第一列右側的空白區）。用 reduced motion 重截結果一樣，所以這是版面本身，不是截圖剛好卡在動畫中途 |
| D5 證據的呈現 | 4 | 證據格式一致，看起來可信：一律用「」引原文，`.band` 每條下面有「出處：digiRunner API 管理平台產品頁」；案例寫成「作業：… → 引文 → 連結」三部分；穩定度用 2005、2008、2017／2019、2020 的年份當標題，後面接原文；hero 第一屏就放了一則合規事實。扣分的地方：同一則 `digirunner-open-banking-fsc` 在 hero 與 `.band` 出現兩次，三階段、金融檢查、共通性規範在 `.poster` 與 `.band` 各出現兩次，重複稀釋了證據；具名案例「臺北市政府」藏在政府 tab 裡，預設看不到；案例成果的字級比旁邊的老照片弱很多 |
| D6 窄螢幕 | 3 | 375 寬的第一屏安排得好：h1 兩行、說明、雙 CTA、圖、事實都在，也沒有橫向捲動（scrollWidth 375）。往下大多只是把桌機版堆疊起來：產業 tab 在約 2,041px（第 2.5 屏），第一則案例成果在約 3,979px（第 5 屏），沒做到 brief「兩次捲動內找到產業入口與一則有成果的案例」，主要被三張案例老照片各占滿一屏推下去。產品 bento 的放大片段在 375 一樣被裁（「無密碼」「異常」「MC」）。整頁 14,612px，比 1280 寬的 10,866px 長很多 |

要改的地方：

- D2：五種場地色和超過五種字級是這個方向最明顯的違規，要收斂到「一個底色加一個 accent，段落才換整片色」，字級回到五種以內。19 世紀版畫只能當氛圍，P3 要的是畫出「既有系統 → 昕力產品 → 新服務」的接點，至少 hero 或產品段要有一處讀得出接點。h1 的「API」「AI」不要用另一種字寬去強調
- D3：每段只留一個第一眼焦點。案例段要讓成果原文比照片先被看到；產品段與 OrientAI 段被裁切的放大字與開關不能比產品名、h2 更搶眼；產業段的四張等重海報要分出輕重，或刪掉跟下方 tab 重複的內容
- D4：處理案例段右欄的半屏空白與 bento 的空格、溢出，讓間距看起來是有意的，不是排到一半
- D6：375 寬要讓產業入口與第一則案例成果在兩次捲動內出現。案例照片在窄螢幕要縮小或放到文字後面，bento 的片段在窄螢幕不能被裁掉

### 文案與行銷：平均 4.2

| 項目 | 分數 | 理由 |
|---|---|---|
| C1 定位清楚 | 5 | h1「金融與政府的系統接上 API 與 AI」（15 字，在 brief 的 15–25 字內）說出對象與做的事；說明句「昕力資訊（TPIsoftware）研發並導入自有軟體，把 API、資料與 AI 安全接進既有系統；規範要求直接做在產品功能裡。」補上「既有系統」與差異（規範做在產品裡）。兩句合起來和 messaging 定位句一致，品牌詞照 brief 取捨第 3 項放在說明第一句 |
| C2 對受眾的價值 | 4 | 多數段落用讀者的問題開場：「規範要求，已做進產品」、案例的「作業：…」、「依要解決的問題找產品」、OrientAI 的「資料會交給外部嗎？」、「決策者不必在產品原廠和導入廠商之間協調」、「是評估長期合作風險的資料」，都寫結果與風險。扣分在 `#services` 六張服務卡全是「說明待補」，以及 bento 有幾格只列功能（「FIDO2 無密碼 零信任身分驗證」），沒寫解決什麼問題 |
| C3 證據支撐 | 4 | 主張旁邊幾乎都有引用的事實。抽查與 `facts.yaml` 的原文一致：`smartclaim-result`、`smartfilling-result`、`fraud-platform-result`、`orientai-on-prem-data`（「不會。…」照引）、`aiso-llm-support`（70B 在原文內）、`office-names`、`company-milestone-2008-finance`、`company-milestone-2020-brand`、`systalk-ai-onboarding`（四個步驟對得上），都是 confirmed，沒有引用 `to_confirm` 的數字或獎項。ESGswift 那格的「用同一套平台整理」是表述，旁邊沒有引文；服務卡沒有證據位置 |
| C4 CTA 與轉換路徑 | 4 | 主要 CTA「聯絡業務」出現在 header、hero、`#contact`、footer，`#contact` 的卡片寫清楚點了會怎樣（「填寫聯絡表單，說明您的產業、現有系統與想接上的服務，昕力的業務會與您聯絡。」），回覆時間誠實標「待補」。次要 CTA 都照 brief：依產業看方案、看金融業方案、看所有成功案例、認識 OrientAI、關於昕力。扣分：標題寫「談需求，或預約 demo」，按鈕卻只有「聯絡業務」；footer 緊接著再一個一樣的紫色按鈕，重複；政府的入口「看政府與公部門方案」要先點 tab 才看得到 |
| C5 符合 brief | 4 | 8 段齊全，順序照 brief。缺的地方：第 2 段 brief 要求金融、政府兩個入口各一句並直接連結，這裡做成 tab，政府預設隱藏，另外多了一列 brief 沒有的四張法規海報（含「通訊機制」，這是 DigiLism 的事實，不是產業入口）；第 4 段 brief 要求連到產品頁並帶類別詞，但「digiRunner API 管理平台」那格連到 `/products/digilism`，`/products/digirunner`、`/products/gadodido`、`/products/gadoscout`、`/products/greenswift` 都沒有連結 |
| C6 語氣與文字品質 | 4 | 表述簡潔，沒有 AI 腔，也沒有「賦能」「頂尖」「一站式」這類字；「從既有系統談起」「規範要求，已做進產品」都是原創，不是照抄現站。扣分在幾處生硬或重複：「通訊機制」當產業海報的標題讀不懂；金融檢查那則原文是一長串以空格分隔的項目，照引後讀起來很亂，可以只引一段並帶出處；同一則開放銀行事實在第一、二屏出現三次 |

要改的地方：

- C2：服務卡的說明要寫出每項服務替決策者處理掉什麼。bento 純功能的那幾格，標題要改寫成「解決什麼問題」
- C3：ESGswift 那格的表述旁要補引 `greenswift-scope` 之類的原文；服務卡要留證據的位置
- C4：「預約 demo」要有對應的動作文字，或讓標題與按鈕一致；政府入口要跟金融一樣預設就看得到
- C5：產業入口照 brief 改成金融、政府並列的兩個入口，那列法規海報要刪掉或併進去；產品段補上產品頁連結，「digiRunner API 管理平台」要連到 `/products/digirunner`
- C6：拿掉重複出現的事實；過長的原文只引跟主張相關的那一句
