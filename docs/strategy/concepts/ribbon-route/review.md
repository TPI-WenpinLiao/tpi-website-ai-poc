## 評審：ribbon-route（修正版）

評審日期 2026-11-01，由新的 `reviewer` 依 `site-review` 評分。這是使用者選定 `ribbon-route` 後依意見修正的版本；修正前的評分（設計 3.5、文案 3.8）見 git 歷史 `f7f8e1b:docs/strategy/concepts/ribbon-route/review.md`。評審依據 `index.html`、作者附的截圖，以及評審自己用 Playwright（SwiftShader WebGL）在 1280 與 375 寬、不設減少動態下每 0.9 屏與多個補充位置的截圖（不在 repo）；沒有讀 README、`scene.src.js`、`directions.md`、`copy-deck.md` 與舊的 `review.md`。評審依使用者決定，把本輪放寬的「漸層緞帶與 WebGL 場景當主要影像」視為已同意的例外。設計概念階段不判斷通過與否，分數只供參考。

第一印象：5 秒內就看得懂。h1「金融與政府的既有系統／原地接上 API 與 AI」寫出了對象和做的事；下面的白色方塊地圖上，緞帶依序經過「核心系統 → 既有系統 → 昕力的產品 → AI 模型 → 新的服務」，畫的就是接進既有系統這件事。整頁是亮底，和 SYSTEX、Syscom 那種深色發光的畫面一眼就能分開。

### 設計：平均 4.0

| 項目 | 分數 | 理由 |

要改的地方：

- D5：把案例的成果原文當成這一段的主角，字級或位置要比近景圖更搶眼，阻詐那則要有和前兩則對等的呈現。近景圖要畫出各自的作業，不然就退成輔助。穩定度補齊 brief 第 7 段的六項，或說明拿掉哪幾項、為什麼。原因：受監管的決策者要看紀錄，現在成果的視覺權重低於裝飾圖
- D3（建議）：俯視過場這 1.5 屏要有可讀的焦點，或縮短。分岔緞帶要等到產業入口離開畫面才消失
- D6（建議）：375 寬要有到產品、案例的導覽入口；產業入口在窄螢幕不要擠成兩欄

### 文案與行銷：平均 4.0

### 驚豔感（不計分）

桌機動態版是這一輪最有記憶點的地方：白色方塊城市加一條紫、品紅到橘的緞帶，鏡頭從斜視升到俯視，緞帶在畫面上一路往下，接到「規範要求，已做進產品」的分岔，兩條分支各停在一個產業入口上方。概念和定位句綁在一起，不是為了炫而炫。削弱效果的有兩處：俯視那段的方塊渲染偏淡、偏雜，看起來像還沒畫完；分岔緞帶在入口還沒離開畫面時就被水平裁斷，接著消失。後段（產品、OrientAI、聯絡）回到一般的雙欄版面，驚喜感集中在前兩屏。

針對使用者的意見：

- 緞帶是否從 hero 連續到第二段：桌機動態版在固定畫面期間是連續的（y=1000 時緞帶從地圖右側往下走，y=1250 時同一條緞帶穿過 h2 右側往下，y=1500 時分成兩支停在兩個入口上方）。有兩個斷點：畫布底部約 72px 一直有一條白帶，緞帶在那裡被切齊；固定結束後，y≈1620 時分岔上緣被水平裁斷，y=1700 時消失。375 寬的靜態版是連續的。到了第三段，緞帶在另一個框裡以近景重新出現，視覺上不相連
- 手機版線條是否有用途：有。375 寬沒有左側直條了，唯一的長線條就是那條緞帶，從地圖接到兩個產業入口，把讀者帶到「找產業」的任務。剩下的只有聯絡按鈕左邊約 56px 的橘色短帶，作用不明顯但很小
- 字級與排版是否還雜亂：整齊多了。1280 寬只有四級（h1 約 112px、h2 52px、內文 20px、小字 16px），375 寬也是四級（30.7、27.4、18、16px），只有 h1 特別大，各段 h2 都在同一個位置。剩下的問題：375 寬的 h1 與 h2 幾乎一樣大，第一屏的 h1 在手機上失去主導感；桌機 h1 的 112px 佔掉大半個第一屏
