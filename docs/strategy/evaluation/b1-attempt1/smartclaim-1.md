# 評審：AI 智能理賠解決方案 `/solutions/smartclaim`（r03）

第一批（#200）第一次評審，評審時的代號 r03，對象是 PR #205 在 `c4ce310` build 出的 `/solutions/smartclaim`，對照 `docs/strategy/briefs/smartclaim.md`。`reviewer` 只看匿名化的截圖與 `dist/` 的 HTML。

截圖：[`../b1-new/smartclaim-1280-first.jpg`](../b1-new/smartclaim-1280-first.jpg)、[`../b1-new/smartclaim-375-first.jpg`](../b1-new/smartclaim-375-first.jpg)、整頁 [`1280`](../b1-new/smartclaim-1280-full.jpg)、[`375`](../b1-new/smartclaim-375-full.jpg)

第一印象：在 1280 與 375 的第一屏都能在 5 秒內看懂，這是給保險業理賠作業用的 AI 方案（處理診斷書、單據，從立案做到派件）。右側的緞帶世界靜態圖標了「診斷書及單據 → AI 智能理賠解決方案 → 自動理賠引擎」，和首頁看得出是同一個網站，也不會被認成一般的科技圖。整頁的版型照 brief 一段換一種。比較弱的是幾處標題斷行很難看，相關產品那段右側空了一大塊，全頁從頭到尾都是白底。

## 評審依據不足

- `docs/strategy/design-principles.md`「內頁共用的規則」的「影像」列寫「至少 4 張介面片段」，`briefs/smartclaim.md`「取捨」第 2 項決定用 3 張，並寫「交設計概念階段確認」，但設計原則裡沒有這個確認的結果。D2 拿不準這是不是違反原則，這次照 brief 不扣分，只在理由裡註明
- `design-principles.md`「各模板怎麼呈現」的 offering 只寫了 digiRunner。第一屏「服務對象要讀得到」的規則用的是「金融」「政府」，解決方案頁的對象是保險業，要怎麼寫、要不要連到金融頁，原則沒寫，D1、D2 是類推判斷的
- `design-principles.md`「內頁共用的規則」的「段落的分隔」寫「P5 的判斷組之間換底色」，但沒寫內頁要怎麼分組。digiRunner 的例子只有規格表和對應表墊灰底；像這頁一樣沒有表格段的頁面，全白算不算違反，判斷不了（D2、D4）
- 介面片段裡的狀態名稱「已啟用」（HTML 裡有，畫面上是紫色方塊）不在事實原文裡。brief 寫片段「只畫事實寫得出的……狀態名稱」，`design-principles.md` 只寫可以畫「狀態名稱」，沒說「已啟用」這類泛用的 UI 狀態算不算事實，這次沒有扣分
- `docs/strategy/search-intent.md`「AI 智能理賠 解決方案」的共同子題有「導入步驟」，「昕力 智能理賠」也記了前幾名都沒有「導入方式」，但事實庫沒有相關原文，brief 的「取捨」「待確認」也都沒處理這個子題。S2 因此扣了 1 分，但製作端其實沒有事實可以寫，這個缺口該由 brief 決定是承接、交給別頁，還是列入待確認
