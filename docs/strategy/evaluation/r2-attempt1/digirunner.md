# 評審：digiRunner 產品頁 `/products/digirunner`（匿名代號 r03）

第二輪（#187），評審時的代號 r03，對象是 PR #191 在 `177237c` build 出的 `/products/digirunner`，對照 `docs/strategy/briefs/digirunner.md`。`reviewer` 只看匿名化的截圖與 `dist/` 的 HTML。

## 評審依據不足

1. 事實原文要照引（`CLAUDE.md`「內容規則」、brief「照原文列清單的段落」：`text` 只能加標點、換行，字不改）和 C6 的「沒有錯字」互相衝突，判斷不了要不要扣分。`fact:digirunner-deployment`（「支援地、雲端部署」）與 `fact:digirunner-ai-usage-log`（「完整錄所有AI使用歷程」）的原文本身就缺字。製作者照規則照引，讀者看到的是錯字；brief 又指定前者當 hero 的證據點。`site-research` skill 或 `facts-source.yaml` 的規則沒有寫：現站原文有明顯漏字時，可不可以補字並註記。
2. `design-principles.md`「offering：digiRunner 產品頁」的段落表只寫了每段「有什麼圖」，沒有寫「規格表段落與案例列能不能另加裝飾圖」。第 4 段寫「無」，判斷是「不要放圖」還是「不要求放圖」需要推論。本次照「不要放圖」評，扣在 D2。
3. `design-principles.md`「內頁共用的規則」的 375 寬寫「一段不超過約 1.5 個螢幕高」，但 brief 第 5、7 段要求的事實清單（各 4–6 則原文，有些超過 60 字）在 375 寬時本來就會超過。兩份文件沒有說哪一個優先，D6 的扣分因此偏保守。
