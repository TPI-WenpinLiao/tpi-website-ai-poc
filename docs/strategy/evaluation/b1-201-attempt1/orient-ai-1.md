# 評審：OrientAI 企業級 Agentic AI 平台 `/orient-ai`（r02，第一次）

第一批（#201），評審時的代號 r02，對象是 PR #206 在 `9121f11` build 出的 `/orient-ai`，對照 `docs/strategy/briefs/orient-ai.md`。設計 3.7 未通過，修正後由新的 `reviewer` 重評，通過的評審檔在 [`../reviews/b1-new-orient-ai.md`](../reviews/b1-new-orient-ai.md)。這次的截圖已被重評時的截圖覆蓋，畫面可從 `9121f11` 重新 build 取得。

第一印象：5 秒內看得出來。第一屏的 h1「OrientAI 企業級 Agentic AI 平台」加上 tagline「讓 AI Agent 跨系統做事，權限與成本由企業統一管控」，說明句寫出對象是「對資料隱私要求高的金融與政府單位」。所以這是給金融與政府、可以控管的 AI Agent 平台。右邊緞帶世界的圖標了「業務系統 → OrientAI → AI Agent」，跟文字講的是同一件事。往下捲，各段的組織比第一屏鬆散：兩段介面片段下面的清單散在 1280 寬的整列上，留下不少空白。

## 設計：平均 3.7，未通過

| 項目 | 分數 | 理由 |
|---|---|---|
| D1 第一屏的辨識度 | 5 | 1280 與 375 的第一屏都看得到 h1、tagline、說明句、三則證據點與「預約演示」。做什麼（AI Agent 跨系統執行任務）、給誰（金融與政府單位）、差在哪（權限、用量與紀錄在企業的管控內）三件事都用文字寫出來。影像是同一個世界的靜態圖，標籤寫系統類別，換掉圖意思不變；不靠發光物件撐辨識度 |
| D2 與設計原則一致 | 3 | 對得上的地方：h1 是全頁最大的字，上方沒有小標，上層節點只出現在麵包屑；hero 依序是說明句、證據點、動作；相鄰段的版型都不同；`ui` 用 3 次；4 張介面片段都標「示意」，只畫功能名與狀態，沒有假數字；接點圖左中右分別是現有系統（中性色）、OrientAI（紫）、AI Agent（暖色）；InPageNav 有中文段名，375 寬右緣露出下一項。違反的地方有兩處：(1) 介面片段版型規定「h2、說明句與 2–4 則事實原文在 9–12 欄」，但第 2 段與第 4 段把「應用場景」與 MCP、全週期管理的事實放到片段下方，跨整列排。第 2 段標題欄在說明句下方空出約 170px，第 4 段的事實段落只佔左半，右半空著，接近 P5「一段的文字擠在一側、另一半螢幕空著」。(2) 相關文章索引列的縮圖面積不小（約 227px 寬），其中兩張是發光方塊、手指觸控平板，正是 P3「不會怎麼呈現」點名的科技圖。縮圖來自文章封面，但訪客看到的是這一頁 |
| D3 視覺層級 | 4 | 每一屏都有一個大的襯線 h2 當焦點，閱讀順序跟 brief 的段落順序一致。相關文章的標題用小字級，符合「段落標題」的規則。差在：第 2、4 段片段下方的「應用場景：」清單與 MCP 小節離 h2 很遠，看起來像是夾在兩段之間的獨立內容 |
| D4 版面與節奏 | 3 | 段落之間的節奏有變化：白、淺灰（第 4–6 段一組）、白、淺紫色帶、白、深紫帶，三組判斷用底色分開。但段落內部的間距不一致：第 2 段的四個應用場景分在 x=64 與 x=656 兩欄，中間隔半個畫面；第 3 段的事實兩欄高度不齊，數據孤島那句在左欄的空白之後才出現；第 5 段右欄只有兩句短原文，兩句之間隔約 90px；第 7 段說明句和規格表之間因為段落圖空出約 180px；hero 的按鈕下方到第 2 段之間又空出約 130px |
| D5 證據的呈現 | 3 | 有證據：4 張介面片段把事實裡的功能名畫出來，第 7 段的硬體建議是真的規格表，事實原文用內文字級放在表述下方。但證據大多是內文裡的功能清單，視覺上跟一般段落沒有區分。hero 的三則「證據點」只是 2–4 個字的功能名，撐不起證據的份量；「應用場景」四個名詞排成散開的兩欄，看起來不像紀錄。事實庫沒有 OrientAI 的客戶與成果 |
| D6 窄螢幕 | 4 | 375 寬是重新安排過的：第一屏有 h1（兩行）、tagline、說明句、三則證據點與按鈕，圖放在按鈕下方；介面片段接在說明句之後；接點圖改成上中下三層；應用場景排成兩欄；段落圖不顯示。差在第 3 段從接點圖到事實清單約 1,400px，大約 1.7 個螢幕高，超過約 1.5 個螢幕 |

要改的地方：

- D2：第 2、4 段的事實原文照介面片段版型收進 h2 所在的那一欄，或改成這一段能放進去的量，不要排到片段下方跨整列。相關文章的縮圖縮小，或者挑掉發光物件、手指觸控這類圖
- D4：讓段落內部的間距一致。不要讓四個短詞橫跨 1280 寬，事實兩欄的高度要排齊，右欄只有兩句時不要拉出大空白，規格表的說明句和表格之間不要因為段落圖空出一截
- D5：讓功能事實看起來像「紀錄」，不要只是內文清單。hero 的三則證據點要讀得出各自是什麼功能，應用場景放在它所屬的片段或說明旁邊

## 評審依據不足

- `design-principles.md`「內頁的版型」的規格表寫「整段墊 `--color-bg-subtle`」，brief 第 7 段也寫 `fill: subtle`；但「段落的分隔」寫成判斷組之間才換底色。第 4–6 段已經是一整組淺灰，第 7 段如果也墊淺灰就會跟前一組連在一起。兩條規則在規格表緊接著淺灰組時互相衝突
- 介面片段版型只寫了「2–4 則事實原文在 9–12 欄」，沒寫事實較多或含清單時要放哪裡
- `design-principles.md`「各模板怎麼呈現」只寫了 digiRunner 與金融頁；OrientAI 的 hero 圖要沿用首頁的圖還是新做，評審拿得到的文件裡沒有這個決定的紀錄
- D5 與 C3 的 5 分錨點以「數字、案例、客戶、成果」為證據，rubric 沒寫只有功能與規格事實的產品頁要做到什麼程度才算 5 分
- `messaging.md`「統一用詞」寫主要轉換的按鈕在 header、hero、頁尾都用「聯絡業務」，brief「CTA」則指定這頁用「預約演示」（`cta: demo`）。兩份文件的規則互相衝突
