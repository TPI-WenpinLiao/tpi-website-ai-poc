## 評審依據不足

1. `competitors.md` 只觀察競品首頁，沒有任何一家的產業頁或金融方案頁。D1 只能拿首頁的觀察推論
2. `design-principles.md` 是為首頁寫的：P5 的「8 段」「兩次捲動內找到產業入口與案例」、P1 的「金融、政府兩個產業名稱」都以首頁為對象。產業 hub 頁該照什麼版型密度、案例要在第幾屏出現、hero 圖該用什麼，沒有寫
3. hero 要不要放聯絡按鈕沒有定案：`briefs/finance.md`「CTA」寫「hero 是否加按鈕交設計概念」，`design-principles.md` 只定了首頁 hero 要有主要 CTA
4. 「產品總覽」段算不算有理由：`briefs/finance.md`「段落結構」沒有這段，但同一份 brief 的「schema 缺口」第 2 列建議模板用 `industry` 反查列出相關產品。brief 沒寫清楚反查出的產品要成為獨立一段，還是只是資料來源
5. `hasPart` 與子頁卡片的關係：`content-model.md` 的 `sections` 說明寫「段落已連到的子頁不再列在子頁卡片」，但 JSON-LD 規則寫 `hasPart` ← 子節點頁面，沒說子頁卡片不顯示時 `hasPart` 要不要保留
6. 事實原文照引與可讀性的取捨：messaging 與 P2 要求事實照 `text` 原文引用，但沒說片段式的原文能不能加標點或拆成清單呈現
7. rubric 的「介於兩個錨點之間時取低的」：錨點只有 5、3、1，沒說清楚 4、2 分什麼時候給。本報告採「介於 3 與 5 之間就給 4」的讀法
8. `briefs/finance.md` 第 8 段只說要精選案例，沒說案例卡要不要寫成果。P2 的「作業 → 成果 → 連結」格式寫的是首頁 brief 的段落
