# 評審：試點新版 digiRunner 產品頁

評審時的代號 r03，對象是 `main`（eb0592e）build 出的 `/products/digirunner`，對照 `docs/strategy/briefs/digirunner.md`。`reviewer` 只看匿名化的截圖與 `dist/` 的 HTML，不知道這一組是什麼，也沒看到其他組的分數。以下是評審的原文，只調整標題層級。

截圖：[`../new/digirunner-1280-first.jpg`](../new/digirunner-1280-first.jpg)、[`../new/digirunner-375-first.jpg`](../new/digirunner-375-first.jpg)、整頁 [`1280`](../new/digirunner-1280-full.jpg)、[`375`](../new/digirunner-375-full.jpg)。理由裡的 `page-<width>-partNN.jpg` 是整頁圖由上而下每 1600 px（375 寬是 1400 px）切成的段落。

第一印象：第一屏 5 秒內就看得出這是一個 API 管理平台的產品頁，用途是「關鍵系統的 API 與 AI 串接」，也看得到證據點和兩個動作。看不出是給誰用的：「金融與政府」只出現在頁內導覽的一個連結文字裡。亮底白色方塊配紫色緞帶的影像，和競品的深色科技物件分得開。

## 評審依據不足

1. `design-principles.md` 的 P1「會怎麼呈現」只寫首頁：要求第一屏出現「金融」「政府」產業名稱、h1 寫定位句。產品頁的 hero 要不要也露出服務對象沒寫
2. `design-principles.md` P5「影像」說「產品與案例頁至少 4 張圖，由介面片段滿足」，但 `briefs/digirunner.md` 的段落表沒有任何一段寫要放哪張圖、畫什麼。缺圖算製作違反原則還是 brief 沒要求，界線不清
3. `briefs/digirunner.md` 第 1 段把 `fact:digirunner-trial-30-days`（「30 天免費試用」）列為 hero 證據點，但 messaging `IT-7` 與 brief 第 9 段都要求寫「免費」時連同 `fact:digirunner-cloud-trial-terms` 的條件。兩條規則在 hero 互相衝突
4. `briefs/digirunner.md` 第 6 段寫「金融、政府各一項」，但 `fact:digirunner-open-banking-3-stages`、`fact:digirunner-oas` 也列在同一段的事實欄。拆成 5 張卡算不算偏離 brief 不清楚；`fact:digirunner-oas` 不屬於金融也不屬於政府，該放哪裡也沒寫
5. `rubrics/seo.md` 的 S6 錨點 3 寫「欄位比頁面內容少」。產品頁的 JSON-LD 幾乎一定比頁面內容少，`content-model.md` 也只規定 name、description 等欄位。沒說要不要有 `offers`、`featureList` 才算「一致」
6. `rubrics/copy-marketing.md` 的 C2 錨點 3 說「多數段落是功能清單」，但 `briefs/digirunner.md` 要求第 2、3、5 段的清單直接用事實原文。照 brief 做就一定有大量功能清單，C2 該看說明句還是看整段，rubric 沒寫
