這是 `needs-design` 的階段二。階段一已經在 PR #142 出貨（`bb240b8`），使用者已加上 `design-approved`。上表是階段二計畫的階段 2–4，因為 `status.mjs` 要求從 1 開始編號，所以這裡改成 1–3。

使用者決定（2026-10-28）：needs-input 的三項（法規或政策、cookie 類別、三語文案）還沒有答案，選「先做機制，有 ID 才顯示」。只有設定 `PUBLIC_GTM_ID` 的 build 才顯示橫幅、載入 GTM；`src/data/consent.ts` 是 `draft: true`，有 ID 但還是 draft 時 build 失敗；`CONSENT_ALLOW_DRAFT=1` 只給 `scripts/consent/gtm.mjs` 的測試 build 用。

階段 1 已完成：
- `src/lib/consent/state.ts`：`localStorage` 的 key 是 `tpi-consent`，存 `{ version, granted, at }`；`consentParams`、`wantsGtm`、`revokes`。單元測試 `scripts/consent/state.test.mjs`
- `src/lib/consent/gtm.ts`：同意後才注入 gtm.js；consent default 與 update 以 arguments 物件推進 dataLayer
- `src/lib/consent/page.ts`：`consentProps(locale)` 檢查 ID 格式與 draft
- `ConsentBanner` 的 script：沒有選擇時才顯示橫幅；`data-consent-action` 是 accept、reject、save；撤回已同意的類別時重新載入頁面；關閉後的焦點回到打開它的按鈕，那個按鈕已經隱藏時改到 `<main>`
- `PageLayout` 用動態 import 載入 `ConsentBanner`。靜態 import 會讓每一頁多帶約 5 KB 的 CSS，實測過；改成動態 import 後，沒有 ID 時 `dist/` 只有 `/design-system` 不同
- 驗證：沒有 ID 的 build 跟階段一的 build 比對，只有 `design-system.html` 不同；`PUBLIC_GTM_ID=GTM-TEST0000` 加 draft 時 build 失敗並印出 draft 的訊息；`gtm-bad` 時印出格式錯誤；加上 `CONSENT_ALLOW_DRAFT=1` 能 build，三語首頁都有橫幅

階段 2 已完成：
- `scripts/consent/gtm.mjs` 接在 `package.json` 的 `check:before-lighthouse` 裡、`scripts/forms/contact.mjs` 之後。它先確認 `dist/` 除了 `/design-system` 都沒有 `data-consent-config` 與 `googletagmanager`，再用 `GTM-TEST0000` 加 `CONSENT_ALLOW_DRAFT=1` build 到 tmpdir，以 Puppeteer 檢查 `/`、`/en`、`/vi`、`/privacy`。在本機跑一次約 75 秒
- 原生 modal dialog 的 Tab 走過最後一個控制項後，會跳到瀏覽器自己的 UI，headless 下焦點落在 `document.body`。所以檢查的是「焦點沒有跑到 dialog 後面的頁面」，不要求焦點一直留在 dialog 裡
- 反向驗證：在 `ConsentBanner` 的 script 裡加上無條件的 `start()`，4 頁全部失敗（同意前就請求 gtm.js、出現 dataLayer），之後已經改回
